# Правила роботи з rc-pwm-bridge

- Спочатку читай `docs/decisions.md`, `docs/requirements.md`, `docs/architecture.md`, `docs/roadmap.md` і `docs/open-questions.md`; foundation — історичний контекст із застарілими пропозиціями.
- Перша версія: один RC-вхід насоса, ESP32-C3, Cytron MD20A, нативний ESP-IDF. Не додавати Arduino framework, радіозв'язок або канал запалювання в поточний обсяг.
- Документація й ручні інструкції українською; вхідні промпти Spec Kit та конституція англійською.
- `.agents/skills` і `.specify` містять інтеграцію CLI 0.12.17. Конституцію v1.0.0 у `.specify/memory/constitution.md` ухвалено 2026-10-28; попередній файл був нератифікованим шаблоном. Шаблони plan/spec/tasks синхронізовано з конституцією; встановлені skills збережено.
- Загальні поради skills про необов'язкові тести, test-first, припущені defaults чи автоматичні дії не скасовують правил проєкту. Для змін поведінки потрібні змістовні тести, без обов'язкового test-first циклу; ліміт уточнень не дозволяє вигадувати відповіді на блокувальні питання.
- Виконуй тільки явно запитану фазу Spec Kit. Промпти в `speckit-iteration/` є входом; результати зберігай у `specs/<ідентифікатор>/`. Явно встановлюй `SPECIFY_FEATURE_DIRECTORY`, не покладайся на ім'я Git-гілки чи залишений активний feature іншої ітерації.
- Під час `speckit-specify` автоматично створюй або перемикай відповідну feature-гілку ітерації, зберігаючи наявні файли й зміни користувача. Каталог артефактів усе одно задавай через `SPECIFY_FEATURE_DIRECTORY`. Не коміть і не пуш без відповідного завдання користувача. Не прошивай плату й не керуй навантаженням автоматично.
- Винось апаратні залежності з переносимого ядра. Без затвердженого профілю плати не вигадуй GPIO; без рішень Q02–Q06 не оголошуй апаратну конфігурацію придатною.
- PWM LOW на MD20A — brake. Не описуй це як ізоляцію живлення, coast або доведений нуль витрати. Не перенось схему зовнішнього flyback-діода з low-side MOSFET на H-bridge.
- Тестуй змінену поведінку; відокремлюй host-тести, збірку та фізичне прийняття. Не заявляй непроведені перевірки. Зберігай наявні файли й роботу користувача.
