# Відкриті питання

Питання не блокують створення промптів. Вони блокують лише відповідний подальший дизайн, реалізацію або прийняття. Відповіді записувати в decisions та специфікацію етапу, не приховувати за defaults.

| ID | Що визначити | Коли закрити |
|---|---|---|
| Q01 | E01 закрито для зафіксованого macOS arm64 environment: SDK commit/submodules, tools та Python wheelhouse/хеші перевірені; чистий offline replay і перевірка SDK залежностей пройшли. Докази — `specs/01-foundation/verification/build.md`, pins — `tools/environment/environment.lock.json`. Тимчасові локальні шляхи перед використанням перевіряються повторно. | Закрито для зазначеного environment; clean target build і фізичне прийняття — окремі перевірки 01 |
| Q02 | Контактний дизайн визначено: D17 підтвердив C3 rev v0.4, 4 MB і native USB; D18 прийняв pinout та живлення 3V3/GND, D19/D20 визначили RC=GPIO3, PWM=GPIO0 та перемичку DIR–GND на MD20A без GPIO1 для [профілю](../hardware/esp32-c3-supermini-profile.md). Окрема схема/continuity більше не блокує програмну підготовку. Залишаються зовнішній bias, реальні напруги/якість живлення та startup waveform; одночасне USB VBUS + external 3V3 не прийняте як перевірений режим. Невідомі заводські дані допустимі за D13. | H01 design знято; фізичні H02/H03 — до відповідного стендового прийняття |
| Q03 | Рівні, endpoints, frame rate, jitter та radio-loss поведінка RC-тестера і приймача; узгодження рівнів та захист входу. За D21 у 01 — документальні вимоги й pending/gate; фактичні дані RC не блокують SC-004 SuperMini. | Документальна основа 01; фактичні рівні/conditioning — 03 до підключення, timing/loss — до прийняття capture 03 |
| Q04 | Допустимі ширини й періоди, фільтрація, округлення, реакція на одиночний invalid, overflow та втрату capture; вимірювані допуски. | 02/03, до реалізації відповідної поведінки |
| Q05 | Timeout (100 мс лише пропозиція), бюджет затримки cutoff, кількість valid frames, low-команда та arming/recovery, watchdog і діагностика. | 05; до цього вихід дозволений лише в ізольованій перевірці без насоса |
| Q06 | Ревізія MD20A, перевірка постійної перемички DIR–GND і фактичного напрямку (D20), живлення/ground, запобіжники, незалежне аварійне відключення, reset bias, startup current, перехідні процеси та теплові межі/тривалість тесту. За D21 відкладені фактичні дані драйвера не блокують SC-004 SuperMini у 01. | Документальна основа 01; фактичні ревізія/інтерфейс/перемичка MD20A — 04 без насоса; силовий тракт і напрямок насоса — 06 до роботи з насосом |
| Q07 | Напруга/струм/тип запалювання: пряме навантаження, живлення блока чи керуючий вхід; ізоляція, вихідний каскад, гістерезис, спільні/незалежні faults та інтерлоки. | 07; не блокує 01–06 |
| Q08 | Конкретний додатковий ESP32 та його плата/периферія/профіль. | 08; не блокує v1 |
| Q09 | Конкретна Nano (класична ATmega328P чи інша), toolchain, таймери, логічні рівні, точність часу й ресурсний бюджет. | 09; не блокує v1 |

Приймач може продовжувати видавати валідні імпульси після втрати радіоканалу. Міст не може визначити цю втрату лише зі свіжості PWM; потрібне налаштування й окрема перевірка failsafe приймача.
