## Робочий процес

Конституцію ухвалено за [вхідним промптом](../speckit-iteration/constitution-prompt.md). Подальші Specify → уточнення → Plan для кожного етапу запускаються лише за окремими запитами. Tasks та Implement — окремі команди після перевірки артефактів. Див. [порядок запуску](../speckit-iteration/README.md).

Кожен каталог містить англомовні `specify.md`, `plan.md` та український `manual-step.md`. Згенеровані результати розміщуються у `specs/<ідентифікатор>/`, а не поверх промптів. Явний `SPECIFY_FEATURE_DIRECTORY` зберігає двозначні номери roadmap без залежності від стандартної тризначної автонумерації CLI.

## Межі прийняття

Перевірки додаються разом із функцією; 06 не є першим тестуванням. Етапи 03–05 перевіряються без робочого насоса. До контрольованого підключення у 06 потрібні прийнята поведінка 05 і перевірений силовий стенд. Невідомі плата/GPIO/допуски/timeout не стають defaults лише через приклад у foundation.

Збірка не доводить boot safety; host-тест не доводить фізичний cutoff; наявність firmware не доводить завершення стендових перевірок. У кожній ітерації результати й недоступні сценарії фіксуються окремо. Питання запалювання, інших ESP32 і Nano не блокують 01–06.
