# Дослідження проєкту 02

Дата: 2026-10-28. Технічні вибори плану базуються на [spec.md](spec.md), D14/D36/D37 та існуючому коді 01; це не результати тестування 02.

## RCH-01 — Переносимість та збірка

**Рішення**: strict C++11, існуючий `bridge_core`, value types без I/O, heap і платформних заголовків; host suite CTest без нової бібліотеки. Target використовує pinned IDF 5.5.6; точні tool hashes — `tools/environment/environment.lock.json`.

**Причина**: відповідає R03 та вже вибраним D14 контрактам. Обидва CMake targets 01 наразі явно перелічують `startup.cpp`, тому новий source необхідно включити окремо в host і target; host control test має лінкувати core без platform adapter. **Альтернатива**: включити ESP-IDF у заголовки або взяти новий test framework — відхилено через непотрібну залежність і відсутність потреби.

## RCH-02 — Числова карта

**Рішення**: спершу перевірити 900 ≤ width ≤ 2100; для valid `width ≤ 1000` → 0, `width ≥ 2000` → 100, інакше `(width - 1000 + 5) / 10` цілочисельно. Середня гілка має операнди 1001–1999, результат сумування 6–1004; переповнення й unsigned underflow відсутні. Міжмежові значення тестувати разом із критичними endpoints.

**Причина**: точне округлення 0,5 вгору та відхилення invalid до clamp за D36. **Альтернатива**: clamp перед validation може перетворити invalid на 100%; float додає непотрібну невизначеність округлення.

## RCH-03 — Стан і час

**Рішення**: розділити nullable last-valid result/time, останній validation status, latch capture fault і фактичну команду. Вхідні події несуть явний монотонний час у мкс; host fake clock керує подіями, а ядро не читає годинник. Див. [контракт](contracts/control-core.md). Fault latch і output 0% не залежать від оновлення розрахунку. Clear лише повертає до disarmed.

**Причина**: D36/D37 і заборона production arming в 02. **Альтернатива**: один duty для розрахунку й виходу суперечить збереженню результату при fault; таймер 100 мс або auto rearm передчасно вирішують Q05.

## RCH-04 — Залежності та межа доказів

**Рішення**: повторно перевіряти 01 environment lock і збирати host/target окремо; фізичні H02/H03 01, параметри RC/виявлення capture 03, вихід 04 і failsafe 05 залишаються gates відповідних етапів. **Причина**: 01 не прийнята фізично, а compiler pass не доводить сигнал на контактах. За D38 це не блокує завершення 02 після її власних критеріїв і перевірки потрібної програмної основи 01. **Альтернатива**: визнати залежність прийнятою за наявністю firmware — відхилено. Подальша фізична валідація потребує окремого дозволу та погоджених числових меж.
