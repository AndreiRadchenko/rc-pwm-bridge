# Модель даних 02

## Вхід і результат

| Сутність | Поля та інваріанти |
|---|---|
| Подія вимірювання | `width_us`: беззнакове 32-бітне ціле 0…4294967295 мкс; `time_us`: 64-бітний беззнаковий монотонний timestamp у мкс, єдиний clock domain; категорія `measurement` або окрема `capture_fault`. Fault не потребує придатної width. |
| Валідація | `valid` при 900…2100 включно; інакше `invalid_width`; `capture_fault` відокремлено. Немає валідної команди для invalid. |
| Розрахунок | Ціле 0…100%, наявність окрема від значення: початково немає valid, і це не те саме, що валідний 0%. |
| Стан | Disarmed або Fault (зафіксований capture fault); `last_valid_time_us` має окрему ознаку наявності. `effective_duty=0`, `permission=false` завжди в 02. |

## Переходи

| До / подія | Результат |
|---|---|
| Startup | Disarmed, немає valid та часу, effective 0, permission false. |
| Будь-який стан / valid | Оновити розрахунок і last-valid час; fault не знімається, effective 0. |
| Будь-який стан / invalid width | Зберегти розрахунок і last-valid час, fault автоматично не виникає; effective 0. |
| Будь-який стан / capture fault | Зберегти попередній розрахунок/time, latch Fault, effective 0. |
| Fault / явне clear | Disarmed, permission false, effective 0; збережені значення не дають дозволу. Умови виробничого clear/rearm — 05. |

Час надходить у невід'ємному неспадному порядку; це передумова межі, а не доказ свіжості. Однаковий час допустимий, обгортання не допускається. При регресії часу вимірювання відхиляється без оновлення last-valid; повідомлений capture fault усе одно фіксується з командою 0%. Це не підміняє Q05. Втрату сигналу та overflow виявляє 03, повідомляючи явну подію за визначеним там контрактом.
