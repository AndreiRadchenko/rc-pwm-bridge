# Контракт ядра 02

Контракт поведінки для стандартного C++11; конкретні назви типів можуть бути обрані під час реалізації без зміни семантики. Ядро синхронне, не виконує I/O, не читає годинник і не керує GPIO. Оркестратор серіалізує виклики та подає події одного монотонного clock domain у мкс.

## Межа введення

- `update_measurement(width_us: uint32, time_us: uint64)` приймає цілу ширину і час події. `update_capture_fault(time_us: uint64)` повідомляє про помилку без числової ширини. Події різні: поєднання fault і width не інтерпретується як valid вимірювання.
- `clear_fault()` явно знімає latch тільки в моделі 02 і залишає disarmed; цей виклик не визначає або дозволяє виробниче відновлення 05.
- Час кожної прийнятої події — неспадний відносно останньої прийнятої події (рівність допустима), протягом життя об'єкта без wrap. Якщо час менший, вимірювання відхиляється з `time_order_error` без зміни стану, статусу вимірювання, розрахунку чи last-valid. Повідомлений capture fault має пріоритет: навіть із регресивним часом fault фіксується і фактична команда 0%, часи й розрахунок не оновлюються, а виклик повідомляє `time_order_error`. Це помилка контракту, не вигаданий операційний cutoff. Джерело гарантує монотонність та відповідає за порушення; під'єднання/поведінку системи при clock fault визначають відповідні наступні етапи.
- Статус обробки відокремлює accepted event від `time_order_error`. Класифікація вимірювання: valid/invalid width; подія capture fault — окрема. `last_valid_time` змінюється тільки від прийнятого valid, включно з valid під fault.

## Результат і порядок

1. Початково disarmed, fault відсутній, жодного valid/time, effective duty 0%, permission false.
2. Прийнятий width: спочатку перевірка 900…2100 включно. Invalid не обмежувати як duty, не замінює попередній розрахунок і час. За відсутності попереднього valid значення відсутнє, effective 0%.
3. Лише valid: clamp до 1000…2000; 1000 → 0%, 2000 → 100%; усередині `(width_us - 1000 + 5) / 10` цілим діленням. Вся арифметика виконується після перевірки гілок, тому навіть максимальна вхідна width не переповнює її. Запам'ятати результат і час.
4. Capture fault негайно фіксує latch, без зміни last-valid; ефективна команда 0%. Пізніший valid оновлює розрахунок і last-valid час, не знімаючи latch. Invalid ширина сама не встановлює fault.
5. `clear_fault` та будь-який valid не створюють operational arming. У 02 для всіх станів effective duty 0 і permission false. Значення карти є внутрішньою/діагностичною величиною, не командою на апаратний PWM. Відсутність події не породжує timeout: Q05 вирішує cutoff і recovery до робочого застосування.

## Адаптерна відповідальність

03 відповідає за capture, період, overflow і надання валідного часу/явного fault; 04 — за фізичний PWM 1000 Гц, endpoints і MD20A; 05 — за freshness, cutoff budget, arming, watchdog і recovery. 02 не гарантує реального часу чи електричного рівня. LOW на MD20A — brake; окремий незалежний power cutoff і bias потрібні для фізичного прийняття. Немає припущення про виявлення втрати радіо за самими PWM імпульсами.
