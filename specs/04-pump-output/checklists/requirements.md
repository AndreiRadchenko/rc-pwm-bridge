# Checklist якості специфікації: PWM до MD20A без насоса

**Мета**: перевірити повноту та якість вимог 04 перед окремим Plan.\
**Створено**: 2026-10-30\
**Feature**: [spec.md](../spec.md)\
**Фаза**: перевірка якості як частина Specify; окрема фаза Checklist не запускалась.

## Якість змісту

- [x] CHK001 Немає нових деталей реалізації: вимоги описують спостережуваний вихід, режими й відмови; задані hardware/platform межі успадковані, а технічні вибори M04 залишені Plan.
- [x] CHK002 Описано цінність для оператора: перевірити форму PWM і LOW без насоса до робочої інтеграції.
- [x] CHK003 Сценарії US1–US3 пояснюють дії/очікування оператора; технічні терміни дозволів і результатів розрізнені в обсязі та сутностях.
- [x] CHK004 Усі обов'язкові розділи активного spec-template заповнені українською; додатковий розділ уточнень записує відповідь користувача.

## Повнота вимог

- [x] CHK005 Маркерів NEEDS CLARIFICATION не залишилось: B04 закрито відповіддю A, D57 у spec та docs/decisions.md.
- [x] CHK006 Вимоги FR-001–013 мають спостережувані результати; M04 однозначно вимагає числових технічних меж до залежної реалізації/вимірювань, без вигаданих defaults.
- [x] CHK007 Критерії SC-001–006 перевірювані: точні шість точок, 1000 Гц/задані duty з наперед визначеними M04 допусками, сталі endpoints, скінченна сесія, fault, охоплення 100% FR. Невизначений M04 блокує відповідний physical pass.
- [x] CHK008 Критерії формулюють результати на сигнальному виході й для оператора, не вибір API, таймерної роздільності чи структури коду.
- [x] CHK009 Сценарії охоплюють запуск/завершення тесту, шість точок, переходи, DIR–GND, startup/reset/bootloader/upload, faults і діагностичне навантаження.
- [x] CHK010 Граничні випадки включають endpoints, відмови/частковий setup, invalid/time-order, capture fault/resync, відсутній reader, reset у тесті та невідомі електричні умови.
- [x] CHK011 Обсяг обмежений 04 без насоса; operational permission/Q05, brownout/watchdog та навантаження мають власників 05/06, розширення 07–09 відкладені.
- [x] CHK012 Залежності, припущення й gates мають джерела та межі: фактичні software результати 01–03, відкриті H02/H03/Q03/Q06, закритий B04, Plan-owned M04.

## Готовність feature до планування

- [x] CHK013 Усі FR-001–013 пов'язані зі сценаріями/SC і методами доказу в таблиці простежуваності.
- [x] CHK014 US1–US3 покривають основні дії оператора та failure paths; фізичні перевірки відокремлені від програмних.
- [x] CHK015 Описані результати й умови їх перевірки дозволяють окремий Plan; жодний критерій не позначений уже виконаним за фактом створення spec.
- [x] CHK016 У spec не обрано механізм PWM, API, build flags або новий GPIO; згадки профілю/SDK/ядра — прийняті залежності, не новий дизайн реалізації.

## Примітки перевірки

- Перевірка 1: виявлено один продуктовий вибір B04. Користувач обрав A; вимоги входу/виходу, сценарії, критерії та реєстр рішень синхронізовано з D57. Повторна перевірка також розрізнила перехід до наступного кроку від завершення всієї сесії та повну послідовність від очікуваного дострокового припинення за fault: **16/16 пунктів якості виконано**.
- Скінченний тест — одноразова послідовність 0/25/40/50/80/100% із поверненням у LOW, не довільне runtime керування. Повний набір пар переходів перевіряється програмно; фізично — погоджена послідовність і fault-переривання. Це усуває потребу в додатковому command source.
- M04 навмисно не заповнено числами в Specify: користувач доручив Plan тривалості/паузи; технічні допуски, електричні межі, прилад/методика та числовий бюджет реакції мають бути зафіксовані до залежної реалізації й вимірювання. SC-002–005 не можуть отримати physical pass за невизначених застосовних параметрів. Готовність до Plan не є готовністю до Implement або стенда.
- Контактний профіль, invalid hold, last-valid, latch, capture budgets і bounded diagnostics успадковано без переобрання. D10 явно узгоджує branch action з поточним AGENTS.md та старим формулюванням конституції; поправка до конституції не виконувалася.
- Відкриті фізичні результати 01/03 та Q02/Q03/Q06 не замінені defaults. Host/build/physical для 04 ще не виконані. Окремо лишаються Q05 та перевірки 05/06; прийняття 04 не закриває їх.
- Extension hooks: `.specify/extensions.yml` відсутній при pre/post перевірці; виконуваних hooks немає. Plan, Tasks, Implement, апаратні дії та commit/push не запускались.
