# Контракт профілю й апаратних меж

Версія 4, 2026-10-28. FR-004–FR-006,FR-012,FR-013; D09,D11,D13,D17–D21.

## Поточний стан

Є фото SuperMini й погоджений користувачем pinout (D18). Після Plan [ROM/USB-читання](../verification/board-review.md)
підтвердило C3 QFN32 rev v0.4, flash 4 MB (XMC) і native USB одиниці
`c3-supermini-188b0e93032c`. За D18–D20 визначено
[профіль c3-supermini-pinout-01](../../../hardware/esp32-c3-supermini-profile.md):
RC=GPIO3, PWM=GPIO0; DIR–GND перемичкою на MD20A без GPIO1 (D20); зовнішні 3,3 В на 3V3/GND.
У 01 тільки PWM статично LOW; DIR не керується firmware, MD20A/насос від'єднані.
**Контактний дизайн погоджено для програмної підготовки/збірки.** Firmware JSON
ще не створено; фізичні напруги, зовнішній bias і startup waveform не перевірено.

Умови й поля профілю наведено в [моделі даних](../data-model.md). Назва `variant_id`
має значення `c3-supermini-pinout-01`, unit ID наведено вище.
Невідомі виробник/заводська ревізія допустимі за D13; їх не вгадують.
Програмне погодження та фізичне прийняття мають окремі статуси.
SC-004 у 01 за D21 охоплює SuperMini, її живлення й зовнішній PWM bias, разом з
окремим waveform-критерієм SC-006. RC/MD20A у 01 мають документальні вимоги та
явні pending/owner/gate; фактичні дані RC приймаються в 03 до підключення,
ревізія/інтерфейс/перемичка MD20A — у 04, силовий тракт — у 06. Вони не блокують
SC-004 для SuperMini й не є прийнятими за результатами 01.

## Програмний профіль і окремі фізичні перевірки

| Перевірка | Обов'язковий результат |
|---|---|
| Ідентичність | Фото/pinout з hash, ROM chip/flash, власні profile/unit ID та provenance доказів. |
| Розводка | Погоджений pinout за D18 достатній для програмного дизайну; окрема схема/continuity не потрібна для компіляції. |
| Контакти | RC=GPIO3, PWM=GPIO0 на бічних контактах за pinout; два різні GPIO. DIR–GND на MD20A, GPIO1 не використовується (D20). |
| Конфлікти | Розгляд GPIO2/8/9 strap, GPIO18/19 USB, GPIO20/21 UART, GPIO4–7 JTAG та flash/onboard loads; немає мовчазного перепризначення. |
| Рівні | Допустимі напруги й polarity кожного інтерфейсу; RC не підключається до вимірювання/узгодження Q03. |
| Живлення | Дизайн: зовнішні 3,3 В на 3V3/GND. H02: фактичні напруги/живлення; одночасне USB+external power не вважається перевіреним. |
| Bias | Зовнішній стан PWM до app_main/reset, вплив на straps та сумісність майбутнього MD20A; номінали не вгадуються. |
| Погодження | `design_approved` для підготовки/збірки; `bench_ready_01_gpio_only` додатково потребує H02/H03. Reviewer/date, hash critical fields; зміна полів потребує повторного review. |

Майбутній preflight завершується помилкою до генерації GPIO-конфігурації, якщо
profile absent/design-unapproved, чип не C3, flash невідомий, ролі конфліктують або
немає джерела контактного дизайну. Він не блокує D18–D20 через відсутність окремої
схеми/continuity або вимірювань H02/H03. Факт успішної генерації/збірки сам не є
фізичним прийняттям. GPIO0 не використовується для зовнішнього 32 kHz crystal.

## Розділення Q02/Q03/Q06

- **Q02 / H01**: ідентифікація, погоджений pinout, pins, flash і USB; контактний
  дизайн визначено D17–D20. H02/H03 — окремі фізичні gates живлення/bias/waveform,
  не передумова підготовки чи компіляції цього профілю. Portable host дизайн незалежний.
- **Q03 / H04**: виміряти RC-рівні й визначити input conditioning до підключення.
  Для обов'язкової GPIO-only перевірки 01 RC може залишатися від'єднаним; відсутність
  RC parser/capture/arming шляху перевіряється оглядом. Це не прийняття capture 03.
- **Q06 / H05**: документальний контракт MD20A PWM/DIR/ground та задум силового
  захисту; actual driver identity/інтерфейс перевіряється до інтеграції 04, силові
  струми/transients/тепло та незалежне emergency power cutoff — до 06.
  Документальна основа 01 не закриває ці фізичні перевірки.

PWM LOW MD20A — brake. До схем H-bridge не додається зовнішній diode лише за
прикладом low-side MOSFET. Фізичний emergency cutoff не є firmware GPIO або watchdog.

## GPIO-only прийняття 01: H02/H03

MD20A й насос від'єднані. Оператор погоджує power bench і bias SuperMini до подачі
живлення. Вимірюється контакт PWM GPIO0, а не драйвер чи потік насоса.

До першого вимірювання в `verification/hardware.md` обов'язково фіксуються числа:
максимальний допустимий PWM LOW, похибка/калібрування приладу, bandwidth,
sample interval, найкоротший виявлюваний імпульс, trigger/pretrigger, тривалість
спостереження й кількість cold starts/reset. Межі виводяться з перевіреного
інтерфейсу/профілю та можливостей приладу; без цих чисел **H03 blocked**.
Підміняти їх типовим digital threshold аналізатора або добирати після вимірювання не можна.

На цьому етапі немає даних про прилад/схему bias, тому числові електричні допуски
не видані за погоджені. Це явний input фізичного прийняття, не невирішений алгоритм
startup. Операторські записи H02/H03 не створені; GPIO/електричне прийняття не пройдено.

Обов'язкові 01: cold start і ручний reset від моменту подачі живлення в межах
погодженої методики, з PWM LOW; DIR GPIO-ініціалізації немає.
Bootloader/upload/brownout/watchdog recovery мають окремі записи status/owner у
04–06. «Імпульс не виявлено» стосується лише зафіксованої resolution/методики,
а не доказу відсутності імпульсу будь-якої тривалості чи повної boot safety.
