# 03-rc-capture — Один RC-вхід та діагностика

Стан: заплановано, не розпочато. Залежності: 01-foundation,02-control-core. Вимоги: R05,R09,R11,R12.

## Перед роботою

Виміряти рівні RC до підключення MCU, endpoints, період і jitter; записати поведінку при від’єднанні та втраті радіозв’язку. Насос залишається від’єднаним.

Відкриті питання: Q03,Q04. Перевірити прийняття залежностей за фактичними результатами, а не наявністю файлів.

## Порядок

1. У Codex викликати `$speckit-specify` з вмістом [specify.md](specify.md).
2. Прочитати специфікацію; закрити питання, що блокують цей етап, за потреби через `$speckit-clarify`.
3. Окремо викликати `$speckit-plan` з вмістом [plan.md](plan.md).
4. Перевірити план і відповідність конституції. Tasks та Implement виконуються лише окремими запитами.

Для скриптів установлювати `SPECIFY_FEATURE_DIRECTORY=specs/03-rc-capture`. Вихідні файли належать цьому каталогу, незалежно від поточної Git-гілки.

## Критерій завершення

Ширини й свіжість одного входу вимірюються з погодженими допусками; invalid не маскується діагностикою чи потоком подій.

Результат майбутньої реалізації записати в `specs/03-rc-capture/verification/`: що перевірено програмно, що зібрано, що перевірено фізично, за яких умов і що лишилося pending. Створення промптів, spec чи plan не завершує етап.
